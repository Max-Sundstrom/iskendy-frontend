# Облачная демоверсия · 16.10.2026

Задача владельца: открывать текущий интерфейс с телефона и продолжать тестирование
при выключенном Mac. Это отдельный демонстрационный стенд, не production ресторана.

## Состав и изоляция

Исходная точка — публичный commit `72a0ea81aed3a3b9edb3035b90d6a6a905eca583`.
Рабочая ветка — `feat/cloud-demo-20261016`. Исходный dirty checkout
`frontend-mobile` сохранён; реализация выполнена в чистом `iskendy-frontend`.

GitHub Pages публикует только `dist-demo/` из отдельной ветки `gh-pages`.
Публичный frontend-репозиторий и существующая авторизация GitHub используются
без новых секретов, OAuth-разрешений, зависимостей и платного тарифа.
Ни основной backend-репозиторий, ни production-деплой не меняются.

Сборка явно использует `mode=mock`, синтетические фикстуры и MSW. Отправка
реальных заказов, отзывов и аналитики отсутствует. Не включаются legacy HTML,
экраны персонала, production service worker, `.env`, карты исходников и архивы.
Неизвестные API блокируются; backend-прокси отсутствует. Уведомления и звук
имитируются существующими mock-адаптерами.

Проверка в браузере обнаружила, что диагностический `onUnhandledRequest`
MSW мог пропустить неизвестный запрос в сеть. Последний явный catch-all
обработчик теперь возвращает 501 для любых неизвестных `/api/...`, включая
неподдерживаемый метод. Production API не менялся. В тесте реальный статический
сервер отвечает на этот путь 404, а браузер получает именно 501 от worker.

При первом открытии включён интерактивный ввод тестового номера. Выбор сценария
явно сбрасывает данные демонстрации; обычное обновление страницы их сохраняет.
Номера: 112 — готовим; 102 — готово; 997, 998, 996 — выданы.
Оценки 1–5 и комментарии обрабатываются только локальными фикстурами.
Файлы можно выбрать, но доставка вложений и сообщений управляющему по-прежнему
ждёт настоящего API; интерфейс показывает ограничение.

## Адреса

GitHub Pages размещает проект под `/iskendy-frontend/`. Только демоверсия
получает этот base; штатная production-сборка сохраняет `/` и `/board`.
Роутер читает логический путь и добавляет base к переходам и ссылкам.
`board/index.html` обеспечивает HTTP 200 после прямого открытия и перезагрузки.
Статический хост перенаправляет `/board` на `/board/`, сохраняя query.
Пути `/staff`, `/stats`, `/tv` и неизвестные страницы остаются 404.

## Проверки и обновление

```sh
npm ci
npm run verify
npm run format:check
npx playwright test --config playwright.cloud.config.ts
```

Последняя команда собирает изолированный `dist-demo/` и запускает строгий
статический сервер без SPA fallback. Проверяются iPhone/WebKit, Android/Chromium,
планшет 834 и desktop 1440: прямые URL, обновление, первый заказ, навигация,
все пять эмоций, комментарий, 429, сообщения без API и отсутствие служебных путей.
Эта проверка также добавлена в существующий GitHub Actions CI; доступ workflow
остаётся `contents: read`.

После проверок commit с исходниками отправляется в рабочую ветку и проходит PR CI.
Команда `node scripts/build-cloud-demo.mjs` собирает демо и записывает SHA в
`demo-version.json`. Содержимое `dist-demo/` публикуется в отдельную ветку
`gh-pages`; GitHub Pages разворачивает её независимо от Mac. Публиковать нужно
всю папку, включая `.nojekyll`, без исходников и `node_modules`.
Нельзя заменять её результатом `npm run build`: это production-сборка.

Проверка уже опубликованной версии:

```sh
ISKENDY_DEMO_URL=https://max-sundstrom.github.io/iskendy-frontend/ \
  npx playwright test --config playwright.cloud.config.ts
```

Обновление возможно из любой подготовленной среды с доступом к этому GitHub
репозиторию. Сам хостинг не требует работающего локального сервера. Настройка
отдельного облачного исполнителя Codex этой публикацией не создаётся.

## Приёмка

Три ошибки GitHub Actions run `38819755341` воспроизведены в Linux Chromium:
IssuedCard 282 вместо 258 px, issued OrderTicket 368 вместо 348 px,
NavSwitch 321 вместо 324.421875 px. Файлы шрифтов совпадали побайтно с Mac,
успели загрузиться, CDP подтвердил Onest для всех символов. Причина — целочисленное
округление advances при Linux font hinting в Chromium на масштабе 1×.
`text-rendering: geometricPrecision` вернул все три ожидаемых размера.
Замена unicode-range, font-kerning и optimizeLegibility проблему не исправляла.
Размеры, CSS-токены, файлы шрифтов и допуски существующих тестов не изменены.
Добавлена регрессия: строка приглашения умещается при ширине карточки 342 px,
но естественно переносится при 320 px без горизонтального переполнения.

Снимки Linux: [до](reviews/2026-10-16-cloud/linux-issued-before.png) /
[после](reviews/2026-10-16-cloud/linux-issued-after.png).
Первичные причины в Chromium 153:
[Linux subpixel positioning](https://github.com/chromium/chromium/blob/153.0.8010.12/ui/gfx/font_render_params_linux.cc#L251)
и [geometricPrecision](https://github.com/chromium/chromium/blob/153.0.8010.12/third_party/blink/renderer/platform/fonts/font_platform_data.cc#L244).

Локальный `npm run verify` завершился успешно: **786 unit/component**, **573 E2E**,
**40** пропусков по условиям платформы. Отдельная облачная матрица — **24/24**.
TypeScript, ESLint, токены, production build и бюджеты размера прошли.
Initial JS — 114.29 KiB gzip, lazy JS — 55.86 KiB, CSS — 14.82 KiB.
Подтверждения CI и опубликованного стенда фиксируются в PR этой ветки;
точный SHA развёрнутой версии возвращает `demo-version.json`.
