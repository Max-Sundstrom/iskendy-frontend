## 2. Что решил владелец 23.10.2026

1. Игра запускается по нажатию карточки **«Сыграть»** на экране заказа.
2. **Входа нет.** Гость играет, пока ждёт заказ, без регистрации и паролей.
3. **Рейтинг ведёт бэкенд.** Уточнение того же дня: в v1 рейтинга нет (Q-32, §7).
4. Игру разрабатываем **в облаке и локально**. Проект ведётся в **отдельном репозитории** и потом интегрируется с этим фронтом и бэкендом табло.
5. Игра работает на **телефонах, планшетах и десктопе**.

Это совпадает с решениями комплекта: Q9 — встроенное издание «Искенди», Q10 — награды позже, Q4 — в v1 только гость.

## 4. Схема

```
 Телефон / планшет / десктоп гостя
 ┌──────────────────────────────────────────────────────────────────┐
 │ iskendy.ru/board (этот фронт)                                    │
 │  MyOrders → карточка «Сыграть» ── нажатие ──┐                    │
 │  кэш /api/status (опрос только у владельца) │                    │
 │        │ статус заказа                       ▼                    │
 │        └──► мост src/game/ ── postMessage ─► <iframe sandbox>     │
 │                                             play.<домен> (Q-33)  │
 └─────────────────────────────────────────────┬────────────────────┘
                     │ /api/* (как сейчас)      │ статика игры (v1 без сервера)
                     ▼                          ▼
        FastAPI табло + SQLite         хостинг в РФ (Q-33)
        (Greatjaaack/iskendy)          отдельный репозиторий
```

Правило изоляции (инвариант 12 комплекта, ADR-021): разные origin, деплой, база и секреты. Табло не вызывает игровой сервис, игровой сервис не вызывает табло. Падение игры не ломает экран заказа.

## 5. Поток запуска

1. Экран заказа грузится как сейчас. **До нажатия** нет ни одного игрового скрипта, шрифта, WebGL-контекста и запроса к игровому origin (H1). Первый экран не тяжелеет.
2. Гость нажимает «Сыграть». Мост лениво (своим чанком) открывает полноэкранный оверлей и создаёт в нём `<iframe>`:
   - `src` — origin игры из константы сборки (Q-33), только `https:`;
   - `sandbox="allow-scripts allow-same-origin allow-popups"` (same-origin здесь — origin игры, он отличается от нашего);
   - `allow="fullscreen; gamepad; screen-wake-lock"`, `title` из `src/content/`.
3. Игра присылает `game.ready`. Мост отвечает `host.init`: язык, тема, safe area и **только** публичный номер и статус заказа.
4. Пока оверлей открыт, мост пересылает изменения статуса (`order.status`) из кэша `/api/status`. Свой опрос мост не заводит (ADR-004).
5. Заказ готов → мост шлёт `order.ready`. Игра в пределах кадра ставится на паузу и показывает «Заказ №N готов». Хост тем временем делает всё, что делает сейчас: звук, вибрация, уведомление (docs/01 §8). **Заказ всегда важнее игры.**
6. «Закрыть» (`game.requestClose`) или Esc → оверлей закрывается, iframe уничтожается, фокус возвращается на карточку.
7. `game.error` или iframe не загрузился за таймаут → оверлей показывает заглушку «Игра недоступна» и кнопку «Закрыть». Экран заказа работает дальше (H6).

## 6. Протокол `postMessage`

Источник истины — `docs/EMBEDDING.md` §3 комплекта. Игровой репозиторий публикует JSON Schema из `packages/shared/embed`. Мы держим копию в Zod-схемах моста и гоняем контрактные тесты с обеих сторон (H7).

| Направление | Тип | Данные |
|---|---|---|
| хост → игра | `host.init` | `{ v: 1, locale, theme, safeArea, order?: { publicNo, status, etaS? } }` |
| хост → игра | `order.status` | `{ publicNo, status, etaS? }` |
| хост → игра | `order.ready` | `{ publicNo }` — прерывает заезд |
| хост → игра | `host.pause` / `host.resume` / `host.visibility` | — / — / `{ visible }` |
| игра → хост | `game.ready` | `{ v: 1, version }` |
| игра → хост | `game.loading` | `{ progress }` |
| игра → хост | `game.runEnded` | `{ score, distanceM, isBest }` |
| игра → хост | `game.requestClose` | — |
| игра → хост | `game.error` | `{ code }` |

Правила:
- точный `targetOrigin` при отправке, проверка `event.origin` и `event.source === iframe.contentWindow` при приёме;
- каждое входящее сообщение ограничено по размеру и проверено Zod, неизвестные типы молча игнорируются;
- **никогда** не передаём `claimToken`, `editToken`, `iskendy_guest`, `iskendy_visit`, служебные ключи и URL с номером заказа. В игру уходят только публичный номер с чека и статус. Номер в адрес iframe не попадает (SEC-02);
- токен `host.init.token` (награды) в v1 не используется: награды отложены (ADR-017 комплекта).

## 7. Рейтинга в v1 нет

Решение Максима 23.10 (Q-32): **рейтинга пока не будет.** Следствия:
- игровой сервер, база данных и аккаунты игроков в v1 не нужны. Игра — статические файлы на своём origin плюс мост встраивания;
- лучший результат хранится только на устройстве, в хранилище игры. Safari и Firefox могут очищать хранилище iframe чужого origin (P11), тогда рекорд пропадёт между визитами. Для v1 это допустимо;
- в игровом репозитории это ADR-019: задачи P5-01…P5-08 (сервер, перепроверка реплеев, таблицы лидеров) отложены, P5-09 (встраивание) остаётся. Симуляция остаётся детерминированной, реплеи пишутся локально, поэтому рейтинг можно добавить позже без переделки ядра;
- когда рейтинг вернётся, снова встанет вопрос, где он живёт: отдельный игровой сервис (ADR-012 комплекта) или FastAPI табло.

## 8. Устройства

| Класс | Ввод | Раскладка | Проверка |
|---|---|---|---|
| Телефон (390×844 и меньше) | свайпы, удержание, кнопки BOOST/ITEM | портрет основной, ландшафт поддержан | iPhone Safari, Android Chrome, встроенный браузер Telegram и QR-сканер (CLAUDE.md §3.4) |
| Планшет (768, 1024) | касание; клавиатура, если подключена | портрет и ландшафт | iPad Safari, Android-планшет |
| Десктоп (1440) | клавиатура (подсказки клавиш), геймпад | ландшафт | Chrome, Safari, Firefox |

Общие требования к оверлею хоста: на всю площадь окна (`100dvh`, `env(safe-area-inset-*)`), кнопка закрытия не меньше 44 px, фокус захвачен (Radix Dialog), Esc закрывает, `prefers-reduced-motion` уважается. Если браузер не умеет WebGL2 (`'WebGL2RenderingContext' in window` — проверка без создания контекста), карточка остаётся «Скоро» и не обещает сломанную игру (P14).

## 9. Изменения по репозиториям

### 9.1 Этот репозиторий (гостевой фронт)

Задачи G-1…G-7 в [09-roadmap.md](09-roadmap.md), раздел «Игра». Кратко:
- `src/game/` — протокол (Zod), мост, оверлей. Всё в ленивом чанке. Первый экран (120 КБ gzip) не растёт.
- `GameTile` становится кнопкой: активное состояние по макету Figma (Q-36), флаг `features.gameTile`.
- Origin игры — константа сборки в `src/config/`. Это исключение из правила «внешние ссылки только из `/api/feedback/config`», его фиксирует ADR-021.
- Хранилище не трогаем: мост ничего не пишет в `localStorage`/`sessionStorage`.
- Метрика: одна цель «открыл игру» без параметров. Счёт и номер заказа в Метрику не уходят.
- Маршрутов не добавляем: оверлей не меняет адрес и историю (ADR-020, SEC-02).

### 9.2 Бэкенд табло `Greatjaaack/iskendy`

Минимум для встраивания (Q-34, решает владелец бэкенда):
- одна строка CSP в `backend/main.py`: добавить origin игры в `frame-src`. Без неё браузер не покажет iframe;
- блок нового поддомена в общем Caddyfile (`iskendy_analytic`), если игра едет на тот же сервер (Q-33).

Рейтинга в v1 нет (Q-32), поэтому других правок бэкенда не нужно. Код бэкенда мы не меняем (CLAUDE.md §8).

### 9.3 Репозиторий игры (новый, Q-37)

В корень — весь комплект с Drive. Работа по его `ROADMAP.md`: **жёсткий гейт** — фазы A (архитектура и сценарии) и D0 (Design Agreement) подписаны до игрового кода. Для нас ключевые задачи комплекта:
- **A-05** — подписать контракт встраивания с хостом (этот документ — наша сторона);
- **P5-09** — `platform/host.ts`, Lite-набор ассетов (≤ 3 МБ), чип заказа в HUD, прерывание `order.ready`, возобновление заезда, kill switch; сценарии H1–H9.

## 10. Kill switch

Требование комплекта: скрыть игру без деплоя хоста (O8). Удалённой конфигурации у фронта нет (docs/02 §18), поэтому по умолчанию так:
- быстрый путь — игровой origin отдаёт страницу «выключено», которая сразу шлёт `game.error { code: 'disabled' }`. Хост показывает «Игра недоступна». Деплоя хоста и правок бэкенда не нужно;
- полный путь — `features.gameTile = false` и PATCH-релиз фронта (CLAUDE.md §7, уровень 1);
- поле в `/api/feedback/config` — только если владелец бэкенда согласится (Q-34).

## 11. Тесты и приёмка

- Контрактные тесты протокола: те же фикстуры JSON Schema, что в игровом репозитории.
- Unit: мост отбрасывает чужой origin, чужой `source`, мусор и слишком большие сообщения (A9). Токены не уходят в iframe ни в одном сообщении.
- E2E с **mock-игрой** (статическая страница на втором origin в Playwright): H1 (до нажатия нет запросов к игровому origin), H2, H3 (`order.ready` при смене статуса в MSW), H5, H6 (таймаут и `game.error`), фокус и Esc, ширины 390/768/1024/1440.
- Интеграция по CLAUDE.md §3.3: локальный бэкенд с патчем CSP на временной ветке плюс локальная сборка игры. Статусы двигаем через кассу тестовым паролем.
- Устройства — §8, включая Telegram и QR-сканер.

## 12. Разработка: облако и локально

- Игровой репозиторий живёт по `AGENT_SYSTEM.md` комплекта: Claude Code оркестрирует и принимает, Codex реализует (в том числе ночью), перекрёстное ревью разными моделями.
- Облачная сессия: клон игрового репозитория, `pnpm i`, `pnpm test`, Playwright с предустановленным Chromium. Blender в облаке нет: модели делаются локально или скриптами `tools/blender/`, большие файлы — через git-lfs.
- Локально: игра (`pnpm dev`) плюс этот фронт (`npm run dev`) плюс стенд бэкенда (`docker/` ветки `front` или CLAUDE.md §1). Для проверки встраивания нужен origin игры в `frame-src` локального бэкенда — только на временной ветке, не коммитить.
